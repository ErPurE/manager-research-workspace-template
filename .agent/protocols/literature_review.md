# Protocol: literature_review

## 适用场景

- 单篇论文阅读笔记
- 多篇文献调研与综述
- 概念解释、背景梳理、方案比较
- 需要“理解辅助模式”的研究类输出

## 必做步骤

1. 完成 preflight，读取 runtime
2. 用一句话写清当前核心问题
3. 先定输出落点：
   - 单篇论文笔记 -> `notes/literature/`
   - 综合调研/对比 -> `research/`
   - 原理梳理/思维整理 -> `notes/thinking/`
4. 先搭比较框架，再读细节；比较维度必须同层
5. 只读取当前问题直接需要的论文、笔记、图表、公式
6. 明确区分：
   - 已确认事实
   - 待核实事项
   - 未读到的关键部分
7. 保存成文档时，使用 `core/output_templates.md` 的研究骨架

## 硬规则

- 先讲人话，再讲正式表述
- 先讲大问题和主线，再下钻到细节
- 公式不能只抄写，必须解释物理意义
- 不确定的信息明确标 `⚠️ 需要进一步核查`
- AI 整理出的内容，只要自己没真正理解，就不能直接当结论使用
- 物理文献必须补“物理图像”
- 正式研究类文档末尾必须带“自测区”

## 本地辅助工具

- 需要搜论文时，可视情况使用 `.agent/search_papers.py`
- 需要抓 arXiv 文献时，可视情况使用 `.agent/fetch_arxiv.py`

## handoff 必写项

- 已读取的论文 / 文件
- 已确认的核心结论
- 还没核实的 claim
- 已经失败的检索词、筛选方法或比较框架
- 下一篇要读的论文 / 下一张要看的图 / 下一节要核的公式
