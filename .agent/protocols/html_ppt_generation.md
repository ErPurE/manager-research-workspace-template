# Protocol: html_ppt_generation

## 适用场景

- HTML 汇报页
- PPT 结构与页面规划
- caption 重写
- 汇报叙事重构

## 必做步骤

1. 完成 preflight，读取 runtime
2. 先写清：受众、目标、一句话主结论
3. 先搭“宽 -> 窄”的叙事骨架，再写具体页面
4. 区分：
   - 已确认可讲的结论
   - 需要回查的数据或文献
   - 暂时占位的表述
5. 列出每一页 / 每一段只负责一件事
6. 记录图、caption、数据源之间的依赖关系

## 默认落点

- 正式汇报材料：`research/`
- 内部叙事梳理或草图：`notes/thinking/`

## 硬规则

- 不能沿用旧叙事，只因为旧版本已经存在
- 不能把未核实的说法包装成结论
- 汇报与写作都先讲大问题、主线和层次，再讲具体数据
- 若图或 caption 仍依赖旧数据 / 旧说法，必须显式标出
- 需要用户人工回查的地方，要单独列出，不要埋进正文

## handoff 必写项

- 已完成页面 / 段落
- 已确认主线
- 被否决的旧 framing
- 待补图 / 待补数据 / 待补 caption
- 下一页最合理的写法
