# Protocol: experiment_recording

## 适用场景

- 实验计划
- 实验日志
- 补测任务记录
- 参数追踪与复现实验条件

## 默认落点

- `notes/experiments/`

## 必做步骤

1. 完成 preflight，读取 runtime
2. 判断当前是“计划”还是“已执行记录”
3. 记录完整实验条件，不写“同上次”这类模糊描述
4. 明确写出数据路径、图号关联或对应项目
5. 如果涉及同步、参考时钟或特殊连接，单独列出
6. 给出下一步动作：补什么、复查什么、谁接着做

## 最低记录字段

- 日期 / 时间
- 目标
- 样品 / 器件 / 批次
- 仪器清单
- 关键参数
- 同步 / 参考设置
- 过程摘要
- 数据路径
- 初步结果
- 异常与不确定点
- 下一步

## 硬规则

- 以后所有实验都尽量完整记录参数，便于复盘和追溯
- 若涉及图2后续补测，必须明确记录 `10 MHz` 参考同步是否接入
- 不知道的参数不要补脑；写“未记录/待核实”
- 若本次记录服务于论文图，标出对应图号或任务

## handoff 必写项

- 仪器当前状态
- 已测条件 / 未测条件
- 缺失参数
- 数据存放位置
- 下一个人接手前必须先确认的设置
